## Mobile vs TV code separation (decided 2026-09-08, option C)

### Decision
- Keep the SINGLE `:app` module / single APK (no separate app distribution). Reorganize sources into logical source sets: `src/main` (shared), `src/mobile` (mobile entry), `src/tv` (TV entry/UI).
- Wired in `app/build.gradle.kts`: `sourceSets { getByName("main") { java.srcDirs("src/main/java","src/mobile/java","src/tv/java"); res.srcDirs("src/main/res","src/tv/res") } }` so `mobile`+`tv` merge into `main` and both compile into the one APK.
- Moved files:
  - `src/mobile/java/io/github/togo3/scrcaster/MainActivity.kt` (mobile entry)
  - `src/tv/java/.../TvActivity.kt` + `src/tv/java/.../pages/FullscreenControlScreen.kt` (TV UI)
  - `src/tv/res/values/tv_strings.xml`, `src/tv/res/drawable/tv_banner.xml` (TV resources)
- Deliberately KEPT in `src/main`: the `Tv*` remote-infra classes (`TvSupport`, `TvRemoteController`, `TvPhoneKeyMappings`, `TvGeometryPattern`, `TvEndpoint`, `TvAspectRatio`) because `StreamActivity` (shared streaming screen, used by both mobile + TV) depends on them. Only `TvActivity` + `FullscreenControlScreen` are purely TV UI.

### Why not a full module split
- `:app` already had a working `TvActivity` (LEANBACK_LAUNCHER + tv_banner). The native JNI client (`app/src/main/jni`) is shared by both. A clean `:mobile`/`:tv` app-module split would need a shared `:client` library for the JNI + scrcpy-server asset — high refactor risk, and the build cannot be verified in this environment.
- If later splitting into real modules: extract shared Android lib (JNI + server asset + `Tv*` infra + `StreamActivity`) into e.g. `:client`; then `:mobile` and `:tv` are thin app modules.

## Fixed :app deprecation warnings in app/build.gradle.kts (2026-09-08)
- `sourceSets` main (app/build.gradle.kts): final working config uses the `directories` mutable set with STRING paths:
  `java.directories += "src/mobile/java"`, `java.directories += "src/tv/java"`, `res.directories += "src/tv/res"`.
  - `directories` is a `MutableSet<String>` (string relative paths), so pass STRINGS, not `file(...)`. Passing `file(...)` (File) makes `+=` fall back to `plus`+assign → "'val' cannot be reassigned" error.
  - DO NOT use `srcDir(...)` or `setSrcDirs(...)`: both are deprecated in AGP 9.4.0 AND `setSrcDirs` is effectively ignored, so `src/mobile`/`src/tv` were never added as source dirs → caused `Unresolved reference 'MainActivity'` / `'FullscreenControlScreen'` build failures (Kotlin couldn't find the moved classes). `directories += "..."` is the only form that actually applies.
- Replaced `val x by tasks.registering { }` (deprecated `registering` delegate) with `val x = tasks.register("x") { }`. Fixes line 205 warnings. `preBuild.dependsOn` still works.
- Left the miuix-submodule warnings (r8.maxWorkers, commonTest host tests, FIR runner) UNTOUCHED: they originate in the upstream-locked `submodule/miuix` and patching them would diverge from upstream (violates "keep base identical to miuix"). They are harmless. If user wants them silenced, the only local option is editing `submodule/miuix/gradle.properties` (`android.sync.suppressAgpWarnings=...`), which we avoided.
